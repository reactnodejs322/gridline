## Stable Gridline identifiers

- `gridline.group.new` — create work group
- `gridline.session.newCodex` — create Codex terminal
- `gridline.workspace.directoryCommand` — `cd`/`pwd`/`ls` prompt for the saved default folder used by new groups and terminals
- `gridline.workspace.tokenUsage` — visible cyan weekly ChatGPT meter; clicking it opens refresh settings without hiding the meter. Automatic allowance fetch defaults to 3 seconds, supports 1-second minimum and custom millisecond/second/minute intervals, can be disabled, and caches the last value. Claude's rolling seven-day meter appears only while a Claude process is running in a Gridline terminal. The custom interval applies only to the weekly allowance meter. UI: `gridline/template/main_template/MainTemplateUsageStatusView.swift`; data: `gridline/Sources/Gridline/ProviderUsageService.swift`, `gridline/usage/monitor.py`, and `gridline/usage/claude_usage.py`.
- `gridline.workspace.terminalUsage.disable` — the single global per-terminal usage control. Pausing stops the three-second local log watcher, preserves the last snapshots in memory, and hides each workgroup's IN/OUT row; enabling resumes monitoring and shows the rows. It does not pause the weekly allowance meter. UI: `MainTemplateUsageStatusView.swift`; state/process: `TerminalUsageStatus` in `ProviderUsageService.swift`; reader: `gridline/usage/terminal_usage.py`; visibility: `MainTemplateWorkGroupCard.swift`.
- `gridline.workspace.usageRefresh.auto` / `.interval` / `.intervalEditor` — adjust automatic ChatGPT allowance fetching, its saved interval, and custom time units.
- `gridline.workspace.utilityMenu` — opens the shared palette-aware dropdown panel for workgroup navigation, directory prompt, skill scripts, app tabs, and grid layout; panel and row styling are reusable from `MainTemplateDropdownPanel.swift` and `MainTemplateDropdownActionRow.swift` in `gridline/template/main_template/`

Uses its live terminal folder or saved group folder and installs into the containing Git root. When provider metadata advances past that submission, `workspace.terminalUsageStatusChanged` repeats that ID with turn and cumulative tokens plus the source pipeline. Follow these records by `submissionID`; do not infer tokens from character counts. The counter does not measure PTY/control bytes.
- `gridline.layout.columns` — grid column choice, saved in `workspace.json` and restored on launch

## Debug data

- `events.jsonl` — semantic UI actions, terminal lifecycle events, and safe Codex `PreCompact`/`PostCompact` metadata for the current app run. Gridline clears it and `timeline.jsonl` at every launch; `collect_debug_logs.py` copies new events into the fresh timeline. Gridline Debug's full-width lower log section defaults to Everything. Filters cover prompts, usage, Codex hooks, Python, Swift, UI, builds, and failures; workgroup and free-text search plus filtered copying are supported. Reset logs deletes timeline history, raw events, and saved build diagnostics.
- `collect_debug_logs.py` — while the main hot-reload watcher runs, copies build output and safe UI, Swift, and Python events from `events.jsonl` into `timeline.jsonl`. Gridline appends completed Codex prompt text directly to that structured local file with a matching `submissionID`; the collector never copies prompt text into `events.jsonl`. It tracks event offsets within each run and clears requested logs. The old root `hot-reload-logs.md` is retained without further writes.
- `user-log-view.json` — Gridline Debug updates its current Show, Workgroup, Search, Follow state, and match counts as the UI or timeline changes. `./gridline_debug/inspect-logs.sh showUserlogFilters --format llm` reads that state and prints matching entries as structured JSON with repo-relative code-path file/symbol steps and recorded diagnostic details.
- Gridline Debug shows a scrollable inspector at the top and a full-width live Logs section below it. Drag the white divider up or down to resize the two sections. Logs filter by source/type, workgroup, and text; rows expand to show counts, build output, and color-coded Swift/Python code paths. New rows appear at the bottom; the top **Following** toggle scrolls to them automatically, and **Follow** resumes after pausing. Shell inspection uses `./gridline_debug/inspect-logs.sh --category terminal --group 'terminal 1ABC' --limit 20`.
- Native commands that run on a polling interval do not log successful start/completion events; record failures only, so routine process checks cannot flood the log. Historical `runtime.externalProcess` entries remain in the append-only file but are hidden by the default Terminal submissions filter.
- Terminal target and per-terminal usage diagnostics are written only while the matching Gridline Debug app is open. Terminal target entries identify session/workgroup UUID and terminal kind. Usage entries include aggregate IN/OUT/TOTAL values, Python rows read/parsed, status, reason, and the Swift-to-Python source/function pipeline. Python reader failures include the failing stage and exception class only; never include exception messages or local paths. Do not log terminal text, keystrokes, or terminal-derived title text.
- Swift-to-Python work emits `runtime.pythonProcess` launch/completion entries and `runtime.pythonStage` entries from safe Python stage names, status, exception class, and numeric counts. The reusable bridge is limited to the paired inspector being open; do not include transcript text, prompts, terminal output, credentials, local paths, or exception messages.
- `build/latest-status.json` — last build status/time
- `build/latest-errors.txt` — compact compiler diagnostics; empty means last build succeeded
- `build/latest.log` — full compiler output
- `reports/issue-*.md` and matching `.json` — human-readable and structured selected-element context, code path hints, clicks, and app events
- The inspector listens for focus/title/value/layout AX notifications from the last clicked app and merges them into the click timeline.

## Important boundaries

- SwiftUI changes require compile + app restart; the watcher restarts both apps after successful builds, which ends live Gridline PTYs.
- Reports do not store terminal output, AX field values, credentials, or screenshots.
- **Copy LLM context** includes the clicked element, Accessibility metadata, likely Swift file/action, expected semantic event names, a literal `rg` command, and matching `events.jsonl` lines. Terminal lifecycle events are correlated by session ID; unrelated session starts are filtered out. Code path mapping lives in `GridlineCodeContext.swift`; unmapped controls use an explicit search fallback rather than a guessed source line.
- AX inspection works only for elements exposed by the target app's Accessibility tree. The AX hierarchy is not a promise of Swift source line numbers.
- Keep new Swift files and functions focused so an LLM can load only the relevant 100–150 lines.
